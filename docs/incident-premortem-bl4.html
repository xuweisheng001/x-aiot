BL4 事故的三个特征

  1. 影响面是用户而不是设备。设备侧闭环不受影响，机器照常停机；但用户看不到、控制不了、或者被错误的参数误导。
  2. 扩散速度快。参数库发布 10 分钟到全量客户端，App 发版数小时到大部分用户。止血手段首先是「回滚版本」，其次才是修。
  3. 合规事故不可逆。未同意的数据一旦写入、他人设备一旦被看到，删除也不能撤销「已发生」。这类事故检测靠对账，不靠用户投诉。

02App 入口

INC-4-01 BFF 轮询风暴

触发App 某版本的设备卡片轮询在后台未停止，或去掉了 5 s 间隔改为响应即请求；或 304 路径意外走到 PG。

传播BFF QPS 数倍增长 → 若 304 路径查 PG 则连接池满 → deviceapi 与 auth-svc 若共用 PG 一起变慢 → 进入 BL1 INC-02 认证全拒形态。

检测信号BFF 每用户请求数 P99 > 1 rps 持续 5 分钟；429 比例 > 5%；PG active connections 接近上限；304 比例下降。

止血

  1. 确认 user_id + path 限流在工作（429 在涨）。在工作则 PG 应无压力，只是客户端体验差。
  2. 若 PG 有压力：说明 304 路径查了 PG，立刻把影子版本比对切到只查 Redis（应急开关），登记。
  3. 按 App 版本号灰度下线：BFF 对该 User-Agent 版本返回 Retry-After: 30，逼客户端退避。

恢复发 App 热修版本；老版本强制升级提示。

根治304 路径代码审查项「只允许 Redis」；客户端轮询逻辑单测覆盖前后台切换；BFF 对每个 App 版本的请求速率分布进看板，新版本灰度期间自动比对。

演练模拟客户端以 20 rps 轮询单设备，验证 429 与 PG 连接数不变。

INC-4-02 账号体系故障

触发集团账号服务不可用或 token 校验接口超时。

传播App 与 XCS 全部无法登录 → 已登录用户的 token 在 BFF 校验失败 → 入口全灭。安全告警推送不受影响：推送走设备 → alarm-svc → 推送供应商，不经过登录；用户点开推送后进 App 才会失败。

检测信号登录成功率 < 50%；BFF 401 比例陡升。

止血

  1. BFF 对已签发且未过期的 token 启用本地验签兜底（JWT 公钥本地缓存，不回源），登记。这是 fail-open 的一种，只对已持有 token 的用户放行，新登录仍失败。
  2. 推送文案增加设备关键信息（事件类型、时间、SN 后四位），让用户不进 App 也知道机器停了。

根治token 本地验签为常态而非兜底；账号服务多活由集团负责，BL4 只保证降级路径。

INC-4-03 授权越权

触发BFF 某接口新增时忘记挂绑定校验中间件；或校验用了客户端传的 user_id 而非 token 解析的。

传播任何登录用户构造 SN 即可看他人影子、告警、快照，甚至下指令。这是 BL4 最严重的事故，涉及隐私与安全。

检测信号

  • 单 user_id 在 1 小时内访问的不同 SN 数 > 其绑定数 × 2。
  • 对未绑定 SN 的请求应 100% 返回 404；若某路由 404 比例为 0 而请求量正常，该路由可能漏校验。
  • 每次发版 CI 跑「越权测试」：用 A 的 token 访问 B 的 SN，所有 /devices/{sn}/* 路由必须 404。

止血立即下线该路由或整个 BFF 版本回滚；从访问日志导出被越权访问的 SN 与 user_id 清单交法务与客服。

根治绑定校验作为路由组级中间件强制挂载，新增路由默认继承，无法绕过；user_id 只能来自 token；越权测试进 CI 阻断合并。

INC-4-04 解绑后仍可控

触发BFF 的 binding:{user_id}:{sn} 缓存 60 s TTL，解绑接口没有主动删缓存，或多副本本地缓存未同步。

传播转让二手机后，原 owner 在 60 秒内仍能看状态、下指令。

检测信号cmd_audit 中操作时间晚于该 user 对该 SN 的 unbound_at。每日对账。

止血解绑接口补主动删 Redis 缓存；多副本用 Redis 而非进程内缓存。

根治授权缓存只放 Redis，解绑事务内删；对账 SQL 进每日任务，出现即告警。

INC-4-05 指令重复执行

触发客户端未带 Idempotency-Key，网络超时后自动重试；或 BFF 幂等键 Redis 故障时放行。

传播pause 两次幂等无害；stop 两次第二次 fail 无害；P1 的 job_start 两次则重复加工，材料报废。

检测信号同 user 同 sn 同 action 在 1 s 内两条 cmd_audit。

止血BFF 对 job_start 在 Redis 不可用时拒绝而非放行（不可逆动作 fail-closed）；pause / stop 可放行。

根治客户端必带幂等键（BFF 对无键的写请求 400）；不可逆动作的幂等判定以 PG 唯一约束兜底：job_record(sn, started_at) 5 秒内唯一。

INC-4-06 隐私开关显示错误

触发客户端或 BFF 用 desired 值渲染开关，设备离线或未收敛时界面显示「已关」而设备仍开着摄像头云存储。

传播用户基于错误显示做出判断；一旦被发现是系统性问题，就是合规事故。

检测信号对账任务比对界面上报的显示值（客户端埋点 switch_shown）与影子 reported；不一致比例 > 0 告警。

止血客户端热修强制以 reported 渲染；未收敛显示「同步中」。

根治BFF 的 shadow 接口对开关类字段直接返回三态 {value, state: applied|pending|offline}，客户端只渲染 state，不自己比较。

INC-4-07 App 发版崩溃

触发新版本在特定机型或系统版本崩溃，告警中心或设备卡片打不开。

传播用户收到推送点开即崩溃，看不到告警详情与「我已处理」。设备已停机，安全不受影响，但升级短信会在 10 分钟后触发。

检测信号崩溃率 > 0.5% 且集中于新版本；崩溃堆栈聚类。

止血应用商店暂停该版本分发；服务端对该版本返回精简数据（去掉可能触发崩溃的字段）。

根治分阶段发布（1% → 10% → 100%）与自动回滚阈值；告警详情页做成最小依赖的独立路由。

INC-4-08 推送 token 失效

触发用户换机、重装或系统清理后推送 token 变化，App 未及时上报新 token；或推送服务端未处理供应商返回的 invalid token。

传播这类用户收不到任何告警推送，包括火焰事件。是 BL1 INC-10 漏告警在客户端侧的形态。

检测信号推送供应商回执 invalid / unregistered token 比例 > 2%；有绑定设备但 30 天无有效 token 的用户数。

止血对 invalid token 用户立即降级到短信通道（不等 10 分钟）；App 启动时强制刷新 token。

根治token 上报失败时 App 阻断进入主页并重试；服务端每日清理 invalid token 并标记用户「推送不可达」，告警升级策略对这类用户跳过推送直接短信。

03XCS 云连接

INC-4-09 XCS 云调用阻塞本地加工

触发设备列表接口在加工开始前同步调用；或云端慢但未超时（2.9 s 一直在超时边缘）；或静默期逻辑 bug。

传播用户点「开始加工」后等待数秒；老用户认为联网让软件变慢，关闭云功能或流失。

检测信号XCS APM「点击开始到设备收到指令」P95 上升；云调用耗时分布贴近超时值。

止血服务端下发功能开关关闭 XCS 云功能（客户端每次启动拉取开关）；客户端静默期强制生效。

根治云调用全部异步且不在加工关键路径，代码审查项；超时值按 P99 的 2 倍设定而不是拍脑袋；加工开始延迟作为 XCS 发版门禁指标。

INC-4-10 任务元数据泄露图纸信息

触发XCS 把文件名（如「客户 X 订单 Logo.xcs」）或参数原文放进 job 元数据；或 params_hash 规范化前的 JSON 被误传。

传播events 表与 job_record 中出现用户文件名，违反「图纸不上云」承诺。

检测信号events 的 job 相关字段长度分布（job_id 应恒为 36，material_id 与 param_profile_id 为已知 id 集合，params_hash 恒为 64）；任何不符即告警。

止血job-svc 对四个字段做格式白名单校验，不符直接丢弃并计数；已落库的异常行删除并留日志。

根治设备端与 job-svc 双重格式校验；XCS 侧字段来源只能是 id 与 hash，不允许自由文本；数据字典审计进发版流程。

INC-4-11 云端下发任务到作业中设备（P1）

触发BFF 读影子 work_state==0 后设备本地又开始了任务，云端 job_start 到达时设备正在加工；或影子 30 s 新鲜度内状态已变。

传播设备若不做本地校验会中断当前任务开始新任务，材料报废甚至安全风险。

检测信号同 SN 两个 JOB_START 之间无 JOB_DONE / JOB_FAIL。

止血设备端对 job_start 做本地校验：非空闲一律拒绝并回 cmd_ack fail。云端校验只是减少无效下发，设备端校验才是安全边界。

根治job_start 的设备端拒绝逻辑列为固件红线；云端在 deviceapi 白名单判定中同时读影子，双保险。

INC-4-12 预签名 URL 泄露或未过期（P1）

触发预签名 GET URL 有效期误设为 24 h 而非 1 h；URL 被记入客户端日志或崩溃报告上传；对象未按生命周期删除。

传播持有 URL 者可下载用户图纸。

检测信号对象存储访问日志中同一对象被多个来源 IP 下载；生命周期删除失败计数。

止血吊销对象（删除）；轮换签名密钥使所有未过期 URL 失效。

根治GET URL 有效期 ≤ 1 h 且一次性（下载后设备回 ack 即删除对象）；URL 不进任何日志（日志脱敏规则）；生命周期删除对账。

04参数库

INC-4-13 参数库发布错误全量扩散

触发运营录入功率单位错误（百分比填成毫瓦）、材料 id 对错、或发布脚本把测试库发到生产。发布后 10 分钟内全量客户端可见。

传播用户按错误参数加工 → 切不透或烧焦 → 严重时功率过高引发火焰事件 → JOB_FAIL 与 burnt 标记突增 → 客服工单。

检测信号（任一）

  • 发布后 30 分钟内该 product_key 的 JOB_FAIL 率较发布前 24 小时均值上升 > 50%。
  • burnt / uncut 标记率上升 > 50%（opt-in 样本）。
  • 发布前自动校验：新旧版本同材料参数差异 > 30% 的条目数 > 10 需人工确认。

止血（5 分钟内）

POST /internal/params/releases {product_key, rollback_to: <上一个 version>}   → 生成新 version，内容等于旧版本
客户端下次同步（前台 5 min，启动即拉）拿到回滚版本
对已打开 XCS 的用户：服务端推送「参数库有紧急更新」强制同步

根治发布前差异校验与阈值；发布走灰度（先 1% 客户端 24 h 再全量，客户端按 user_id hash 分桶）；单位与范围在 param_profile 上做 CHECK（功率 0 到 100、速度正数）；测试库与生产库物理隔离，发布脚本不接受跨环境参数。

演练staging 发布一个明显错误的版本，验证差异校验拦截；绕过拦截后验证回滚 ≤ 5 min 到达客户端。

INC-4-14 增量同步顺序错误

触发客户端先应用 added 再应用 removed，而某条目在同一增量中先删后加（回滚场景常见）；或跨多个版本的增量合并逻辑错误。

传播客户端本地库缺条目或有重复 → sha256 校验失败 → 回退内置出厂版本（可能很老）→ 用户拿到过时参数但不知情。

检测信号客户端上报 version 分布出现大量回退到出厂版本；sync 失败率上升。

止血服务端对该客户端版本返回 force_full: true，跳过增量直接全量。

根治增量协议明确顺序（先 removed 后 added）并在服务端生成时保证同一条目不同时出现；客户端增量应用单测覆盖回滚场景；落后 > 20 版本强制全量已在方案中。

INC-4-15 CDN 快照与 API 版本不一致

触发新版本发布后 CDN 仍缓存旧快照；或快照上传失败但 release 已写入。

传播全量同步的客户端拿到旧快照但记录了新 version，之后增量从新 version 开始，永久缺一段变更。

检测信号快照文件内嵌 version 与 URL 中的 version 或 API latest 不等；客户端校验快照内 version 后上报不一致计数。

止血CDN 主动刷新；对不一致的客户端返回 force_full。

根治快照 URL 带 version（/params/LM_S1/v123.json）永不复用，缓存策略 immutable；release 写入放在快照上传成功之后（同一事务顺序）；客户端校验快照内 version 必须等于请求的 version。

INC-4-16 自定义参数多端覆盖丢失

触发用户在 XCS 与 App 都改了同一条自定义参数，最后写入胜出把另一端的改动覆盖；或时钟不同步导致新改动被旧改动覆盖。

传播用户辛苦调出的参数丢失，投诉。

检测信号user_param.updated_at 出现倒退；用户投诉。

止血保留每条自定义参数最近 10 个版本，客户端可恢复。

根治乐观锁：PUT 带 If-Match: <server_version>，冲突返回 409 让客户端合并；不用客户端时钟。

INC-4-17 module_model 错误

触发固件上报的 module_model 与实际模块不符（换模块后未重启上报）；或 P0 手选时用户选错。

传播参数库按错误模块索引，40 W 模块拿到 10 W 参数切不透，或反过来烧焦。

检测信号同 SN reported.module_model 与用户手选不一致；同 SN 短期内 module_model 变化。

止血客户端参数面板显著显示当前模块型号，与机器铭牌对照的提示。

根治模块热插拔检测后立即上报；手选值与上报值不一致时界面强提醒并以上报值为准；参数档带适用模块的功率上限，跨模块使用时提示。

05反哺与推荐

INC-4-18 未 opt-in 数据被写入

触发job-svc 校验影子时 Redis 不可用而放行；或设备端未按 optin 清空字段且服务端校验有 bug；或影子字段名不一致（camera 开关误当反哺开关）。

传播用户明确未同意的加工记录进入 job_record，合规事故，需通知用户与监管。

检测信号每日对账：job_record 中 SN 的影子 reported.job_feedback_optin 为 false 或缺失的行数 > 0。

止血job-svc 对影子不可读时丢弃（fail-closed，与 cf001 nonce 同一方向：合规校验不放行）；删除违规行并留删除日志；法务评估是否需通知。

根治opt-in 校验的 Redis 出错即丢弃并计数；设备端不填字段是第一道；对账任务 P0 必上；字段名在物模型 v1.1 中固定并单测。

INC-4-19 推荐档导致烧材或安全事件

触发推荐档来自某批用户在通风好、材料薄的环境下的高功率参数，普通用户使用后烧焦；极端情况下引发火焰事件。

传播用户信任「官方推荐」而不再试切；一次烧材就是一次差评，一次火焰就是安全事故。

检测信号§9.3 每日安全关联：使用该档任务中 FLAME / OVER_TEMP 比例 > 同材料官方档 2 倍且绝对数 ≥ 3；burnt 标记率 > 30%。

止血

  1. 立即对该档发布 version_removed，客户端下次同步消失；已选中该档的 XCS 会话提示「该推荐已下线」。
  2. 从 job_record 拉出使用过该档的 SN 列表，通知用户。

根治推荐档功率不得超过同材料官方档的 110%（硬上限）；推荐档界面标注样本数与「社区统计，请先试切」；安全关联从每日改为每小时；推荐档灰度（先 10% 用户可见）。

INC-4-20 校正系数计算错误

触发health 字段单位理解错误（0 到 1 当成 0 到 100）；laser_hours 降采样缺失当成 0 或极大值；配置 a、b、c 填错。

传播k_power 对大量设备算出 1.25 上限，功率普遍上调 25%，烧材风险。

检测信号k_power 分布：正常应集中在 1.0 到 1.1；> 20% 设备落在上限即告警。校正输入缺失计数。

止血全局开关关闭校正（接口返回 k=1 与原因「校正暂停」），客户端自动回官方档。

根治输入缺失时返回 k=1 而不是计算；配置变更走与参数发布同样的双人审批与灰度；系数分布进看板并设自动关闭阈值。

INC-4-21 反哺被刷偏

触发少数用户或脚本对某参数 hash 批量标记 good，把不合适的参数推成推荐档；或竞品恶意标记官方档 burnt。

传播推荐档质量下降；若与 INC-4-19 叠加则更危险。

检测信号单 hash 的 good 标记中 top 3 设备贡献 > 50%；单设备日标记数 > 20；标记与 job_record 时间不匹配（无对应加工）。

止血候选生成暂停该 hash；异常设备标记权重置 0。

根治按 SN 去重与单日上限已在方案中；标记必须对应本设备 10 分钟内的 JOB_DONE；推荐样本要求来自 ≥ 30 台不同设备且分布在 ≥ 10 个不同用户。

INC-4-22 job-svc 挂或 lag

触发job-svc 全部副本挂；PG 分片库慢；JOB 事件量超预估。

传播job_record 缺失 → 用户 JOB_DONE 后点标记接口返回 404 → 反哺数据丢失。遥测与告警不受影响（独立消费组）。

检测信号nats consumer info IOT_UP job pending 持续增长；标记接口 404 比例上升。

止血拉起服务；pending 自动追（IOT_UP 保留 72 h）。标记接口对 job_record 不存在时返回 202 并暂存 job_feedback_pending，job_record 到达后合并。

根治job-svc 至少 2 副本；标记暂存机制；job_record 按月分区避免大表慢写。

06订阅（P2）

INC-4-23 entitlement 误伤安全接口

触发某次重构把 entitlement 中间件挂到了路由组根上；或 deviceapi 引入了 entitlement 客户端包做「高级功能」判断。

传播entitlement-svc 故障或未订阅用户的告警确认、停机、OTA 接口返回 403 或 5xx。这是 PRD 唯一不可协商约束的违反。

检测信号CI 依赖扫描 go list -deps 发现 deviceapi / alarm-svc / ota-svc / job-svc / param-svc 依赖 entitlement 包即阻断；BFF 路由表审查；「entitlement 停机」冒烟用例失败。

止血回滚引入依赖的版本。entitlement-svc 故障期间若已误伤，临时把 entitlement 中间件全局短路为放行（所有内容对所有人可见，商业损失可接受，安全不可接受），登记。

根治三重锁定（依赖扫描、集中路由表、停机冒烟）全部进 CI 阻断；架构决策记录写明「任何人不得在安全路径引入订阅判断」。

INC-4-24 支付回调重复或丢失

触发支付平台回调重试导致同一订单两次处理（订阅期被延长两次）；或回调丢失导致已付费用户无权益。

传播用户付费后看不到素材，投诉与退款；或平台多给权益，收入损失。

检测信号每小时对账 subscription 与支付平台订单：状态不一致数 > 0。

止血人工按订单号补权益或修正；对账脚本自动修复明确可判定的情形。

根治回调按 provider_ref 幂等（唯一约束）；主动轮询支付平台补偿丢失回调；权益由 subscription 派生而非回调直接写。

INC-4-25 订阅提醒弹在加工进行中

触发提醒逻辑只看订阅到期时间，不看设备状态。

传播用户加工中被弹窗打断，误触导致 XCS 失焦；体验事故。

根治任何非安全类弹窗在影子 work_state ∈ {1, 2} 时延后；这是客户端通用规则，不只订阅。

07合规

INC-4-26 撤回 opt-in 后数据未删除

触发desired 下发 false 但设备离线未回报，job-svc 以 reported 为准迟迟不触发删除；或删除任务失败无重试。

传播用户撤回同意后数据仍在，超过 24 h 承诺。

检测信号每日对账：desired.job_feedback_optin=false 超过 24 h 且 job_record 仍有行的 SN 数。

止血手动删除；对账脚本自动执行删除并留日志。

根治撤回删除以 desired 为触发（用户意图），不等 reported；删除任务幂等有重试；24 h SLA 在 20 h 时预警。注意这与「显示以 reported 为准」不矛盾：显示要保守，删除要积极。

08BL4 特有的临时关闭项模板

沿用 BL1 §10 登记表，BL4 常见的临时关闭项：

  • BFF 影子 304 路径切只查 Redis
  • token 本地验签兜底
  • XCS 云功能服务端开关关闭
  • 参数库回滚版本（本质是发布，不是关闭，但需登记原因）
  • 校正系数全局关闭 k=1
  • entitlement 中间件全局短路放行
  • job-svc 标记暂存模式
