01背景与目标

1.1 问题

  • 激光加工是有明火风险的作业，用户不敢离开机器；一次任务通常 20 分钟到数小时，用户被迫守在旁边，这是消费级激光机最大的体验瓶颈，也是差评与安全事故的共同来源。
  • 机器已经带摄像头、传感器和 Wi-Fi，但数据不上云：故障只能靠用户描述，客服平均要 3 轮以上沟通才能定位；固件升级靠用户手动下载，升级率低、版本碎片化。
  • 竞品（Glowforge、Creality Falcon 等）已提供云端任务监控与推送，联网能力正在成为购买决策项。

1.2 目标

  1. 安全：任何安全事件端侧 100ms 内停机，3 秒内用户在 App 收到推送；事故率可度量、可归因。
  2. 体验：用户可以离开机器，在 App 里看进度、看画面、暂停停止、收到完成通知。
  3. 运营：固件升级 14 天内覆盖全量在线设备且零刷砖批次；错误码自动进工单，客服一次解决率提升。
  4. 底座：P0 建成的接入、影子、事件、OTA、指令五条链路，是配件联动、耗材健康度、教育 Fleet、售后 Agent 四条业务线的共用底座，一次建对。

1.3 北极星与护栏指标

02用户、场景与用户故事

2.1 目标用户

  • 家庭创客（D1 / S1 / F1 主力用户）：机器放在车库或阳台，作业时想去做别的事；最怕起火与噩梦般的「回来发现烧了一半」。
  • 小微工作室 / 电商卖家（M1 / P2）：一天跑十几个任务，关心排队、耗材、不停机；单机故障就是当天没收入。
  • 教育老师：多机管理需求归 BL5，本 PRD 只保证单机能力可被 Fleet 复用，不做教室功能。

2.2 核心用户故事

US-1 离机监控 作为家庭创客，我希望任务开始后能在手机上看到实时进度和机内画面，这样我可以去厨房做饭而不用守着机器。
US-2 安全告警 作为用户，我希望机器检测到火焰或超温时立刻自动停机并断激光，同时手机马上收到强提醒，这样即使我不在旁边也不会酿成火灾。
US-3 远程干预 作为用户，我希望看到画面不对时能在手机上一键暂停或停止，这样不用跑回去按急停。
US-4 无感升级 作为用户，我希望固件在我不用机器时自动升级并且升级失败会自己恢复，这样我不用去官网下载文件，也不用担心把机器搞坏。
US-5 故障求助 作为工作室用户，我希望机器报错时 App 直接告诉我原因和处理步骤，一键提交工单时客服已经能看到错误码和当时的状态，这样不用来回描述三遍。
US-6 隐私可控 作为用户，我希望摄像头画面默认只在本地处理，云端保存要我明确同意并可以随时删除，这样我才放心把机器联网。

03范围：P0 做什么、不做什么

P0 范围内明确不做（留给后续业务线）
试点机型 1 款（建议 S1，封闭式、传感器最全）+ 模拟器全覆盖全机型矩阵铺开（随固件排期）
联网激活、绑定、影子、在线状态多用户共享设备的角色体系（P1，仅 owner）
五类安全事件链路与告警状态机配件联动（净化器自动启停归 BL2）
任务进度、剩余时间、完成通知、摄像头快照（端侧处理，云端 opt-in）云端视频录制与回放（P2，需法务与存储成本评审）
暂停 / 停止 / 自检三条远程指令远程重启与参数远程修改（需二次确认流，P1）
OTA 灰度、熔断、A/B 回滚、差分包用户自选版本 / 降级（不提供）
错误码上报、App 内原因与建议、一键工单附遥测AI 诊断 Agent 对话（BL6 P1）
累计工时、任务数等使用统计上报耗材健康度计算与复购提醒（BL3 P1）
US 单区部署，遥测不出区EU / APAC 区部署（等真实设备量）

6.2 数据保留与归属

  • 遥测与事件明细：TDengine 区级库，KEEP 90 天；小时级降采样长期保留（健康度与保修判定依据）。
  • 影子最新值：Redis（可从 JetStream 72 h 重放重建）；desired 意图：PostgreSQL（不可再生，必须持久）。
  • 告警处置、指令审计（180 天分区滚动）、OTA 批次与任务、绑定关系：PostgreSQL。
  • 摄像头画面：P0 只内存中转；P2 云存储按 opt-in 与 7 天生命周期。
  • 所有存储只含 SN 与 user_id，身份数据在 PII 平台。

10依赖、风险与开放问题

10.1 依赖

  • 固件团队：DR-01 到 DR-09 进入试点机型排期，这是整个项目的关键路径。
  • 产线：证书签发工位与节拍验证；代工机型走 CF001 激活体系。
  • App 团队：配网、设备卡片、告警中心、指令面板、隐私开关六个界面。

  • 基础设施：EMQX 商业 license 评估、CDN 合同、US 区 K8s 集群与 TDengine / NATS / PG 集群。

10.2 风险与对策

风险影响对策
固件退避 / A/B 未能进第一版不可事后补救，连接风暴与刷砖无兜底列为立项前置条件；未锁定不进迭代
OTA 刷坏一批设备设备云最大单点灾难灰度熔断无跳过通道、全量双人审批做成数据库约束、A/B 回滚

10.3 开放问题

  1. 试点机型选 S1 还是 M1？S1 传感器最全，M1 用户量更大。建议 S1 先行、M1 第二批。
  2. 安全告警升级短信的海外供应商与费用归属（整机线还是售后线）。
  3. 自动升级默认开还是默认关？建议默认开但首次联网时明确询问一次。
  4. 快照是否允许在告警推送里直接展示画面（涉及默认端侧处理原则的边界）。
  5. 联犀目标版本与许可复核结论。
