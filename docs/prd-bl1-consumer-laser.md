## 01 背景与目标

### 1.1 问题

- 激光加工是**有明火风险**的作业，用户不敢离开机器；一次任务通常 20 分钟到数小时，用户被迫守在旁边，这是消费级激光机最大的体验瓶颈，也是差评与安全事故的共同来源。
- 机器已经带摄像头、传感器和 Wi-Fi，但数据不上云：故障只能靠用户描述，客服平均要 3 轮以上沟通才能定位；固件升级靠用户手动下载，升级率低、版本碎片化。
- 竞品（Glowforge、Creality Falcon 等）已提供云端任务监控与推送，联网能力正在成为购买决策项。

### 1.2 目标

1. **安全**：任何安全事件端侧 100ms 内停机，3 秒内用户在 App 收到推送；事故率可度量、可归因。
2. **体验**：用户可以离开机器，在 App 里看进度、看画面、暂停停止、收到完成通知。
3. **运营**：固件升级 14 天内覆盖全量在线设备且零刷砖批次；错误码自动进工单，客服一次解决率提升。
4. **底座**：P0 建成的接入、影子、事件、OTA、指令五条链路，是配件联动、耗材健康度、教育 Fleet、售后 Agent 四条业务线的共用底座，一次建对。

### 1.3 北极星与护栏指标

| 指标 | 定义 | P0 目标 | 类型 |
|---|---|---|---|
| 联网激活率 | 激活后 7 日内成功联网并绑定 App 的设备 / 激活设备 | ≥ 60%（试点机型） | 北极星 |
| 周活设备率 | 近 7 日有作业上报的设备 / 联网设备 | ≥ 35% | 北极星 |
| 重大安全事故率 | 造成财产损失的火灾事件 / 万台·年（含未联网口径对照） | 联网设备较未联网下降 50% | 北极星 |
| 安全事件触达 P99 | 设备事件时间 → App 推送到达 | < 3 s | 护栏 |
| OTA 刷砖批次 | 因固件导致设备不可启动且未自动回滚的批次数 | 0 | 护栏 |
| 摄像头云端存储 opt-in 率 | 主动开启云端画面存储的用户比例 | 只统计不设目标（合规） | 护栏 |

## 02 用户、场景与用户故事

### 2.1 目标用户

- **家庭创客**（D1 / S1 / F1 主力用户）：机器放在车库或阳台，作业时想去做别的事；最怕起火与噩梦般的「回来发现烧了一半」。
- **小微工作室 / 电商卖家**（M1 / P2）：一天跑十几个任务，关心排队、耗材、不停机；单机故障就是当天没收入。
- **教育老师**：多机管理需求归 BL5，本 PRD 只保证单机能力可被 Fleet 复用，不做教室功能。

### 2.2 核心用户故事

> **US-1 离机监控** 作为家庭创客，我希望任务开始后能在手机上看到实时进度和机内画面，这样我可以去厨房做饭而不用守着机器。

> **US-2 安全告警** 作为用户，我希望机器检测到火焰或超温时立刻自动停机并断激光，同时手机马上收到强提醒，这样即使我不在旁边也不会酿成火灾。

> **US-3 远程干预** 作为用户，我希望看到画面不对时能在手机上一键暂停或停止，这样不用跑回去按急停。

> **US-4 无感升级** 作为用户，我希望固件在我不用机器时自动升级并且升级失败会自己恢复，这样我不用去官网下载文件，也不用担心把机器搞坏。

> **US-5 故障求助** 作为工作室用户，我希望机器报错时 App 直接告诉我原因和处理步骤，一键提交工单时客服已经能看到错误码和当时的状态，这样不用来回描述三遍。

> **US-6 隐私可控** 作为用户，我希望摄像头画面默认只在本地处理，云端保存要我明确同意并可以随时删除，这样我才放心把机器联网。

## 03 范围：P0 做什么、不做什么

| P0 范围内 | 明确不做（留给后续业务线） |
|---|---|
| 试点机型 1 款（建议 S1，封闭式、传感器最全）+ 模拟器全覆盖 | 全机型矩阵铺开（随固件排期） |
| 联网激活、绑定、影子、在线状态 | 多用户共享设备的角色体系（P1，仅 owner） |
| 五类安全事件链路与告警状态机 | 配件联动（净化器自动启停归 BL2） |
| 任务进度、剩余时间、完成通知、摄像头快照（端侧处理，云端 opt-in） | 云端视频录制与回放（P2，需法务与存储成本评审） |
| 暂停 / 停止 / 自检三条远程指令 | 远程重启与参数远程修改（需二次确认流，P1） |
| OTA 灰度、熔断、A/B 回滚、差分包 | 用户自选版本 / 降级（不提供） |
| 错误码上报、App 内原因与建议、一键工单附遥测 | AI 诊断 Agent 对话（BL6 P1） |
| 累计工时、任务数等使用统计上报 | 耗材健康度计算与复购提醒（BL3 P1） |
| US 单区部署，遥测不出区 | EU / APAC 区部署（等真实设备量） |

## 04 功能需求

编号 FR-xx。每条给需求描述、验收标准与对应的平台能力（工程仓库中的服务），便于研发拆任务与测试写用例。

### 4.1 联网激活与绑定

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-01 **P0** | 用户在 App 完成 Wi-Fi 配网（BLE 传递凭据），设备首次联网自动激活并出现在「我的设备」 | 配网成功率 ≥ 95%（实验室 3 种路由器）；从配网到 App 显示在线 ≤ 30 s | bootstrap-svc 调度、auth-svc 认证、device 表状态 manufactured → activated |
| FR-02 **P0** | 一机一证：设备用出厂证书 mTLS 接入；证书吊销后 5 s 内被拒连 | 吊销后重连被拒；串用他机证书被拒；ACL 越权发布被 broker 拒绝 | pki-svc（迭代 2）、auth-svc 四步校验、EMQX ACL |
| FR-03 **P0** | 设备绑定到用户账号，同一设备同一账号只有一条生效绑定，解绑保留历史 | 重复绑定幂等；解绑后设备数据不再对该账号可见；绑定记录只存 user_id | device_binding 部分唯一索引 uk_binding_active |
| FR-04 **P1** | 转让 / 二手：原 owner 解绑后新用户可绑定；历史遥测斩断与新用户的关联 | 新 owner 看不到转让前的任务记录 | 绑定历史 + PII 平台删除传导 |

### 4.2 设备影子与在线状态

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-05 **P0** | App 设备卡片显示在线 / 离线、工作状态、当前任务进度、腔温、功率档，数据新鲜度 ≤ 30 s | 作业态每 5 s 一次上报（0.2 Hz），空闲态 60 s 心跳；断网后 ≤ 90 s 显示离线 | pipeline 写 Redis 影子 reported；deviceapi GET /shadow |
| FR-06 **P0** | 用户在 App 修改设备配置（如默认功率上限、屏幕亮度）时，设备离线也能保存，上线后自动收敛 | 离线修改 → 上线 ≤ 10 s 内设备生效并回报；多次修改只保留最新，版本单调递增 | shadow_desired JSONB + version；PATCH /desired；down/{sn}/desired |
| FR-07 **P1** | 设备卡片显示累计工时、本周任务数 | 与设备本地统计误差 ≤ 1% | telemetry_1h 降采样表 |

### 4.3 安全事件链路

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-08 **P0** | 五类安全事件（火焰、超温、倾斜、急停、水流异常）由**设备端本地规则**闭环：断激光、停运动、开报警灯，断网同样有效 | 火焰传感器触发 → 激光关断 ≤ 100 ms（台架测试）；拔网线复测一致 | 固件；云端只做通知、留痕、复核（方案第一设计原则） |
| FR-09 **P0** | 安全事件上云走独立通道，App 收到强提醒（穿透静音的高优先级推送）并显示事件时间、类型、当前画面快照 | 事件 → 推送到达 P99 < 3 s；推送含 SN、事件码、时间、快照链接 | alarm-svc 独立消费组、squelch 5 min、App push |
| FR-10 **P0** | 告警有生命周期：未读 → 已推送 → 用户已确认 → 已处理；用户在 App 点击「我已处理」关闭 | 重复上报不产生重复告警；状态迁移不可逆；可在 App 查看告警历史 | alarm 状态机（条件 UPDATE，affected=0 即 409） |
| FR-11 **P0** | critical 告警推送后 10 分钟用户未确认，升级为短信（海外为 SMS 供应商） | 升级只触发一次；用户确认后不再升级 | alarm-svc 升级循环 escalated_at |
| FR-12 **P1** | 用户可设置紧急联系人，升级短信同时发给联系人 | 联系人手机号只存 PII 平台 | PII 平台 |

### 4.4 远程任务监控

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-13 **P0** | 任务开始、完成、失败、暂停四个节点推送通知；完成通知含用时与快照 | 推送延迟 P95 < 5 s；用户可按类型关闭非安全类通知 | event 上报 + alert-svc 非安全通道 |
| FR-14 **P0** | 任务进行中 App 显示进度百分比、预计剩余时间、当前图层 | 进度与设备屏幕显示一致，刷新 ≤ 5 s | telemetry progress 字段 → 影子 |
| FR-15 **P0** | 用户主动拉取一张机内摄像头快照（端侧拍摄压缩后经云中转，不落云端存储） | 点击到显示 ≤ 4 s；快照仅内存中转，不写对象存储 | RRPC 指令 snapshot + 对象存储预签名 URL 短时有效 |
| FR-16 **P2** | 云端保存任务过程录像并可回放（用户显式开启） | 默认关闭；开启后默认保留 7 天；一键删除；仅区内存储 | 对象存储生命周期策略、PII 删除传导 |

### 4.5 远程控制

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-17 **P0** | App 可远程暂停、停止当前任务，以及触发自检；每条指令有回执与结果 | 在线设备往返 P99 < 2 s；离线设备立即提示不可用（不排队）；回执超时 10 s 提示未知结果并建议现场确认 | deviceapi POST /cmd 白名单 pause / stop / self_check；cmd_ack 回流 |
| FR-18 **P0** | 远程重启、恢复运行等不可逆或有安全隐患的操作 P0 不提供，接口层直接拒绝 | 调用 remote_restart 返回 403 | 白名单外动作 403 code 10003 |
| FR-19 **P0** | 所有远程指令写审计流水：操作者、来源（App / 客服 / Agent）、时间、结果，用户可在 App 查看「谁在什么时候操作了我的机器」 | 审计 100% 落库；客服发起的指令用户可见 | cmd_audit 按月分区 180 天 |
| FR-20 **P1** | 客服在工单侧对用户设备发起自检需用户在 App 确认授权 | 无授权指令被拒；授权 15 分钟有效 | BL6 xpilot 集成 |

### 4.6 OTA 固件升级

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-21 **P0** | 用户可选「自动升级（默认开）」或「有新版本时提醒」；自动升级只在设备空闲、Wi-Fi 稳定时进行，作业中绝不升级 | 作业中收到升级任务延后执行；升级前设备屏幕与 App 均有提示可推迟 24 h | ota-svc 下发 policy.idle_only；固件 OTA agent |
| FR-22 **P0** | 运营侧按灰度档位发布：内部机 → 0.1% → 1% → 10% → 50% → 100%，每档观察 24 到 48 h；失败率超阈值自动熔断且无跳过通道；全量档必须双人审批 | 模拟器「刷坏固件」剧本：1% 档投放故障固件，样本达标后自动 fused 且不扩散；无审批建全量批次被数据库拒绝 | ota_batch CHECK 约束、ShouldFuse、md5 稳定抽样累进 |
| FR-23 **P0** | 设备 A/B 双分区：校验失败或启动失败自动回滚并上报 rolled_back | 注入损坏包：设备回滚到旧版本并可正常作业；云端任务状态为 rolled_back | 固件 + ota_progress 回流 |
| FR-24 **P0** | 优先差分包，无匹配差分回退整包；支持断点续传 | 差分包体积 ≤ 整包 20%；弱网中断后续传成功 | firmware_delta、CDN Range |
| FR-25 **P1** | App 显示版本说明与升级进度；升级失败给出人工介入指引 | 进度与设备端一致 | ota_device_task 状态查询 |

## 05 设备端（固件）需求

这一节必须进入试点机型的**硬件与固件排期**，其中三条是不可事后补救的红线。

| 编号 | 需求 | 说明 |
|---|---|---|
| DR-01 **P0** 红线 | 重连退避纪律出厂固化：间隔 = min(2^n × 1 s, 15 min) + 随机 0 到 30 s 抖动；参数可 OTA 调整 | 退避有缺陷的固件一旦铺出去就是埋在客户家里的连接风暴武器；模拟器「坏固件」剧本用于验证网关能挡住 |
| DR-02 **P0** 红线 | 产线烧录一机一证（X.509，SN 绑定指纹），证书 5 年，支持 OTA 换证 | PKI 链：离线根 CA → 区域中间 CA → 产线签发；节拍 < 2 s / 台 |
| DR-03 **P0** 红线 | A/B 双分区与启动自检回滚 | OTA 安全的最后一道；没有它灰度熔断只能减损不能兜底 |
| DR-04 **P0** | 本地安全规则闭环：火焰 / 超温 / 倾斜 / 急停 / 水流 → 断激光 ≤ 100 ms，断网可用 | 云端只做通知与留痕 |
| DR-05 **P0** | MQTT over TLS（8883）双向认证；Topic 只允许 up/{pk}/{sn}/# 发布与 down/{sn}/# 订阅；持久会话 | 越权由 broker 层拒绝 |
| DR-06 **P0** | 心跳分层：空闲 60 s，作业态 0.2 Hz；间隔可 OTA 调参 | 保有量大时心跳就是主要流量，这是容量应急阀门 |
| DR-07 **P0** | 每条上行带设备端单调序号 seq 与设备时间戳；重连后从断点继续上报 | 云端幂等键 sn + seq；乱序与重发是常态 |
| DR-08 **P0** | Bootstrap 接入调度：开机先请求接入点，返回 retry_after 时按值等待；不可达时用本地缓存接入点直连 | 单元化与容灾的前提 |
| DR-09 **P0** | 标准错误码集与物模型 v1（见 §6） | 未知字段云端透传落明细不丢 |
| DR-10 **P1** | 摄像头端侧快照压缩（≤ 200 KB）与按需上传 | 不做持续视频流 |

### 6.2 数据保留与归属

- 遥测与事件明细：TDengine 区级库，KEEP 90 天；小时级降采样长期保留（健康度与保修判定依据）。
- 影子最新值：Redis（可从 JetStream 72 h 重放重建）；desired 意图：PostgreSQL（不可再生，必须持久）。
- 告警处置、指令审计（180 天分区滚动）、OTA 批次与任务、绑定关系：PostgreSQL。
- 摄像头画面：P0 只内存中转；P2 云存储按 opt-in 与 7 天生命周期。
- 所有存储只含 SN 与 user_id，身份数据在 PII 平台。

## 10 依赖、风险与开放问题

### 10.1 依赖

- **固件团队**：DR-01 到 DR-09 进入试点机型排期，这是整个项目的关键路径。
- **产线**：证书签发工位与节拍验证；代工机型走 CF001 激活体系。
- **App 团队**：配网、设备卡片、告警中心、指令面板、隐私开关六个界面。
- **xpilot**：工单 API 与遥测附件展示（BL6 联动的最小接口）。
- **法务与 PII 平台**：摄像头数据区域性意见、删除传导接口。
- **基础设施**：EMQX 商业 license 评估、CDN 合同、US 区 K8s 集群与 TDengine / NATS / PG 集群。

### 10.2 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 固件退避 / A/B 未能进第一版 | 不可事后补救，连接风暴与刷砖无兜底 | 列为立项前置条件；未锁定不进迭代 |
| OTA 刷坏一批设备 | 设备云最大单点灾难 | 灰度熔断无跳过通道、全量双人审批做成数据库约束、A/B 回滚 |
| 误报导致停机打扰用户 | 用户关闭联网或投诉 | 端侧规则阈值可 OTA 调参；告警 5 分钟聚合；误报率进看板 |
| 摄像头隐私争议 | 品牌与合规风险 | 默认端侧处理、云端 opt-in、7 天保留、一键删除、区内驻留 |
| 业务方不认领指标 | 平台变成技术自嗨 | 立项以业务线为主体；联网激活率与事故率由整机线 PM 背 |
| 真实激活率曲线未知 | 容量与成本估算偏差 | 架构按千万设计、容量按爬坡付费；beta 100 台校准 |

### 10.3 开放问题

1. 试点机型选 S1 还是 M1？S1 传感器最全，M1 用户量更大。建议 S1 先行、M1 第二批。
2. 安全告警升级短信的海外供应商与费用归属（整机线还是售后线）。
3. 自动升级默认开还是默认关？建议默认开但首次联网时明确询问一次。
4. 快照是否允许在告警推送里直接展示画面（涉及默认端侧处理原则的边界）。
5. 联犀目标版本与许可复核结论。
