配件与安全生态 AIoT 产品需求文档

xTool 设备云 BL2 业务线的产品需求：让净化器、灭火器、排烟风扇这些配件从「插在主机旁边的独立电器」变成设备云里有身份、有状态、能联动、能被算寿命的节点。主机作业时净化器自动启停调档，滤芯按实际风量算寿命并提醒，灭火事件上云留痕并推送。全部复用 BL1 建成的接入、影子、事件、指令、OTA 五条链路，配件作为独立设备接入同一管道，与主机通过配对关系绑定。云端联动是增强，本地联动是兜底：云挂了净化器照样跟着主机启停。与《xTool AIoT 平台技术方案》§6 / §7 / §9 / §17 及工程仓库 x-aiot 一一对应。

  • P0 必须 P1 首个迭代交付，是配件联动与灭火留痕的最小闭环
  • P1 应该 滤芯寿命与复购提醒，依赖小时级降采样积累
  • P2 可以 多配件编排与第三方配件接入

01背景与目标

1.1 问题

  • 激光加工产生烟雾与异味，净化器是刚需配件，但当前净化器与主机没有任何通信。用户开始加工前要手动开净化器、手动调档，加工结束忘记关的情况普遍，滤芯白白消耗。
  • 滤芯寿命目前靠「用了多久」估算，与实际风量、材料无关。用户要么换早了浪费，要么换晚了净化效果差、味道大。滤芯是 BL2 最重要的耗材收入，提醒不准直接影响复购率。
  • 灭火器、烟雾传感器这类安全配件触发后没有任何记录。一次灭火事件发生了什么、主机当时在做什么、有没有推送到用户，都无法回答。这既是安全问题也是售后争议的来源。
  • 配件连带率低：用户买主机不一定买配件，因为看不到「买了配件会更省心」的具体价值。联动是配件价值最直观的体现。

1.2 目标

  1. 联动：主机开始作业 3 秒内净化器自动启动并按材料调档，作业结束后延时关闭；云端不可达时本地联动照常工作。
  2. 寿命：滤芯健康度按累计风量加权计算，剩余寿命误差 ≤ 15%，到阈值提前提醒，复购入口交给 BL3 / BL4。
  3. 留痕：灭火器触发、烟雾超阈值作为安全事件进入告警链路，推送用户并与主机 SN、当时任务关联留痕。
  4. 底座复用：配件不新增任何设备到云的通道，用与主机相同的证书、Topic、影子、指令模型，只多一层配对关系。

1.3 北极星与护栏指标

指标 定义 目标 类型
配件连带率 绑定了至少一个联网配件的主机 / 联网主机 首年 ≥ 25% 北极星
滤芯复购率 收到寿命提醒后 60 天内复购的用户 / 收到提醒的用户 ≥ 30% 北极星
联动成功率 主机 JOB_START 后 3 秒内净化器进入运行态的次数 / JOB_START 次数（已配对） ≥ 98% 护栏
联动延迟 P99 主机事件时间 → 净化器 reported 运行态 < 3 s 护栏
滤芯寿命预测误差 预测剩余小时与实际更换时剩余小时之差 / 额定寿命 ≤ 15% 护栏
灭火事件触达 P99 配件事件时间 → App 推送到达 < 3 s（与 BL1 同口径） 护栏

02用户、场景与用户故事

2.1 目标用户

  • 家庭创客：机器在室内或阳台，最在意烟味；买了净化器但经常忘开忘关；希望「不用管」。
  • 小微工作室：一天十几个任务，净化器几乎全天开着，滤芯消耗快，关心「什么时候该换、能不能省」。
  • 已购灭火器的安全敏感用户：为离机操作买了灭火配件，希望真出事时不只是灭火，还要立刻知道、事后有据可查。

2.2 核心用户故事

US-1 不用管的净化器 作为家庭创客，我希望按下开始加工后净化器自己开、自己调档、加工完过几分钟自己关，这样我不用记着这件事，也不会因为忘关白白耗滤芯。
US-2 材料不同风量不同 作为工作室用户，我希望切亚克力时净化器自动开大档、刻木头时开小档，这样既能压住味道又不浪费滤芯。
US-3 滤芯快到寿命提前说 作为用户，我希望滤芯还剩两周左右时收到提醒并能一键下单，而不是等味道大了才发现该换了。
US-4 云挂了也得转 作为用户，我希望家里断网时净化器仍然跟着主机启停，联网只是让它更聪明，不联网不能让它变傻。
US-5 灭火了要告诉我 作为离机操作的用户，我希望灭火器触发时手机立刻收到强提醒，并能看到当时主机在做什么、灭火器什么时候触发的。
US-6 配件也要能升级 作为用户，我希望净化器固件像主机一样自动升级并且升级失败会自己恢复，不用我操心。

03范围：首迭代做什么、不做什么

首迭代（P0 标记）范围内 明确不做（留给后续）
净化器 1 款作为试点配件接入：一机一证、影子、事件、指令、OTA 全部复用 BL1 灭火器、排烟风扇接入（P1，等硬件）
配对：App 内把净化器与主机配对，一台净化器同时只配对一台主机 一台净化器服务多台主机的编排（P2）
云端联动规则：JOB_START → 开机调档；JOB_DONE / JOB_FAIL → 延时关闭；档位按材料映射表 用户自定义联动规则编辑器（P2）
本地联动兜底：净化器固件接收主机局域网 / 蓝牙广播信号启停 第三方配件接入协议（P2）
灭火事件码与烟雾超阈值进安全告警链路，关联主机 SN 与 job_id 灭火器自动补给提醒（P1）
滤芯运行数据上报：风机转速、运行时长、压差 滤芯寿命计算与提醒（P1，需数据积累）
配件 OTA 复用 ota-svc，独立 product_key 与批次 主机与配件固件联合发布（P2）

04功能需求

编号 FR-2xx，避免与 BL1（FR-01 到 FR-32）、BL4（FR-4xx）冲突。每条给需求、验收标准与平台能力。

4.1 配件接入与配对

编号 需求 验收标准 平台能力
FR-201 P0 净化器作为独立设备激活、认证、上线：product_key=ACC_PURIFIER，一机一证，Topic 与主机同规则 复用 BL1 FR-01 / FR-02 验收；配网到 App 显示在线 ≤ 30 s bootstrap-svc、auth-svc、ACL、device 表
FR-202 P0 配对：用户在 App 选择一台主机与一台净化器建立配对；一台净化器同一时刻只能配对一台主机，一台主机可配对多个不同类型配件 重复配对幂等；换主机时旧配对自动解除并留历史；解除后 5 s 内联动停止 accessory_pairing 部分唯一索引
FR-203 P0 配对关系随主机绑定走：主机解绑或转让时其全部配对同时解除 主机 unbound_at 写入后配对 unpaired_at 同事务写入 device_binding 解绑传导
FR-204 P1 配件也出现在 App 设备列表，卡片显示在线、运行态、档位、滤芯健康度 数据新鲜度 ≤ 30 s BL4 FR-402 复用，deviceapi GET /shadow

4.2 云端联动

编号 需求 验收标准 平台能力
FR-211 P0 主机 JOB_START 或 work_state 进入 2（作业）→ 已配对净化器 desired {power_on: true, fan_level: L}，L 由材料档位映射表决定（无材料信息用默认档） 联动延迟 P99 < 3 s；联动成功率 ≥ 98% accessory-svc 规则引擎消费 iot.up.event.* 与影子；deviceapi PATCH /desired
FR-212 P0 主机 JOB_DONE / JOB_FAIL / work_state 回到 0 → 延时 T 后 desired {power_on: false}；延时内主机再开始作业则取消关闭 默认 T = 180 s，用户可在 App 调 60 到 600 s；取消关闭正确 规则引擎定时器，linkage_rule.off_delay_s
FR-213 P0 材料档位映射表云端可配：material_id → fan_level，无映射用 product 默认；映射表随参数库版本化发布 映射变更 10 min 内生效 linkage_rule 表；复用 param-svc 发布纪律
FR-214 P0 联动可关闭：用户在 App 对某配对关闭「自动联动」，关闭后云端不再下发 desired，本地兜底不受影响 关闭后 JOB_START 不产生 desired 写入 accessory_pairing.linkage_enabled
FR-215 P0 联动留痕：每次云端联动写审计（触发事件、目标配件、下发的 desired、结果）；用户在 App 可查 审计 100% 落库 linkage_audit 表
FR-216 P1 主机安全事件（FLAME_DETECTED 等）→ 净化器立即最大档运行 10 分钟（排烟）；灭火器配件收到主机火焰事件不自动触发（灭火由传感器本地决定） 火焰事件后净化器 3 s 内最大档 规则引擎安全规则分支
FR-217 P2 用户自定义联动规则（条件 → 动作）编辑器 — 规则 DSL

4.3 本地联动兜底

编号 需求 验收标准 平台能力
FR-221 P0 主机作业态通过局域网组播或蓝牙广播「作业信号」，净化器固件收到即启动默认档，信号停止后延时关闭 断网台架测试：主机开始作业 3 s 内净化器启动 固件（主机 + 净化器）
FR-222 P0 云端联动与本地联动并存时以「更强」为准：任一路径要求开机即开机；档位取较大值；关闭需两路径都允许 云端下发小档、本地默认大档时净化器运行大档 净化器固件仲裁逻辑
FR-223 P0 净化器 reported 上报当前运行态与「触发来源」(cloud / local / manual)，云端据此统计本地兜底触发次数 reported.trigger_source 字段存在 物模型

4.4 灭火与烟雾安全事件

编号 需求 验收标准 平台能力
FR-231 P0 新增安全事件码 FIRE_SUPPRESSED（灭火器触发）、SMOKE_HIGH（烟雾浓度超阈值）加入 SafetyCodes，走 alarm-svc 独立消费组，级别 critical 事件 → 推送 P99 < 3 s；重复上报 5 min squelch envelope.SafetyCodes、alarm-svc
FR-232 P0 配件安全事件关联主机：告警详情显示配对主机 SN、当时主机 work_state、进行中的 job_id 告警记录含 paired_sn 与 job_id accessory-svc 富化，alarm 表扩展或关联表
FR-233 P0 灭火事件同时触发主机停机指令（stop）与净化器最大档；主机端侧自身火焰检测仍是第一道，云端指令是第二道 灭火事件后 2 s 内主机收到 stop deviceapi POST /cmd source=system
FR-234 P1 灭火器触发后进入「需检查」状态，App 显示更换 / 复位指引；复位前再次触发事件按不同码上报 状态机 armed → triggered → reset 物模型属性 extinguisher_state
FR-235 P1 烟雾浓度持续超阈值但无火焰：推送「通风不足」提醒（非安全通道），并让净化器最大档 与 SMOKE_HIGH 安全码分级：浓度阈值分两档 alert-svc 非安全通道

4.5 滤芯寿命

编号 需求 验收标准 平台能力
FR-241 P0 净化器上报：fan_rpm、fan_level、run_seconds（累计）、pressure_diff（压差）、filter_installed_at 字段进物模型；小时级降采样 telemetry 超级表标签 product_key 区分；telemetry_1h 流
FR-242 P1 滤芯健康度 = 1 − 累计等效风量 / 额定风量，等效风量按档位风量系数累加，压差超阈值时额外折损；写 consumable_health(part='filter') 与实验室实测寿命误差 ≤ 15% accessory-svc 每小时批计算，consumable_health 表（BL1 预留）
FR-243 P1 健康度 ≤ 20% 推送提醒（非安全通道，可关闭），≤ 5% 每周提醒一次；提醒带一键复购入口（BL3 / BL4 承载） 提醒不重复；复购点击进埋点 alert-svc；BL3 复购接口
FR-244 P1 更换滤芯：用户在 App 或净化器上确认更换 → filter_installed_at 重置，健康度回 100% 重置后累计风量清零 desired filter_reset → reported
FR-245 P2 滤芯识别：NFC / 二维码识别官方滤芯，非官方滤芯不计算寿命只提示 — 固件 + 物模型

4.6 配件 OTA

编号 需求 验收标准 平台能力
FR-251 P0 净化器固件走 ota-svc 同一套灰度、熔断、双人审批、A/B 回滚；独立 product_key 批次 复用 BL1 FR-21 到 FR-24 验收 ota-svc

6.3 数据归属与保留

  • 配件遥测与事件：TDengine 同一超级表，标签 product_key 区分；KEEP 90 天；小时级降采样长期。
  • 配对、联动审计、滤芯寿命：PostgreSQL 分片库，只含 SN。
  • 灭火事件留痕：alarm 表长期保留（安全复核依据）。
  • 所有配件数据只含 SN，与用户的关联仍只通过主机的 device_binding。

10依赖、风险与开放问题

10.1 依赖

  • BL1 平台：接入、影子、事件、指令、OTA 五条链路接口冻结；SafetyCodes 可扩展。
  • 配件固件团队：DR-201 到 DR-206 进净化器固件排期，本地联动接收是关键路径。
  • 主机固件团队：作业信号广播（局域网组播或蓝牙）。
  • BL4 App：配对界面、配件卡片、联动开关、滤芯提醒。
  • BL3：滤芯复购入口与订单归因。
  • 硬件：灭火器、烟雾传感器型号与通信方式确认。

10.2 风险与对策

风险 影响 对策
云端联动误关净化器（延时关闭逻辑 bug）导致作业中无排烟 用户吸入烟雾、投诉 关闭需云端与本地都允许；本地信号存在时云端关闭无效；规则引擎只发「建议关」
本地联动信号被邻居主机误触发 净化器乱开 广播信号带主机 SN，净化器只响应配对主机
滤芯寿命算法误差大 复购提醒不准，用户不信任 先用实验室 3 组对照校准系数；提醒文案给区间而非精确天数
灭火事件误报（烟雾传感器被切割烟雾触发） 短信轰炸 SMOKE_HIGH 分两档：高档进安全码，低档走非安全提醒；阈值可 OTA 调参
配件数量翻倍带来的心跳流量 容量 配件空闲心跳 120 s（比主机更长），可 OTA 调参
配对关系与主机绑定不同步 转让后原主机仍控制净化器 解绑事务内传导配对解除

10.3 开放问题

  1. 本地联动用局域网组播还是蓝牙广播？组播依赖同一 Wi-Fi，蓝牙依赖距离；建议双通道，固件团队评估成本。
  2. 延时关闭默认 180 s 是否合适？工作室连续任务间隔常小于 3 分钟，建议按用户类型给不同默认。
  3. FIRE_SUPPRESSED 是否同时触发主机 stop？主机端侧火焰检测通常已先停机，云端 stop 是冗余；需确认不会造成二次干扰。
  4. 滤芯额定风量与档位风量系数由供应商给出还是实验室标定？
  5. 灭火器型号与复位方式（物理复位还是更换）决定 FR-234 状态机。
