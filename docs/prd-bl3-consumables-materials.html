耗材与材料 AIoT 产品需求文档

xTool 设备云 BL3 业务线的产品需求：把激光模块、镜片这些「用着用着就不行了」的部件变成可度量、可预测、可一键复购的耗材；把材料包变成扫一下就带出官方参数的入口。健康度按发光时长乘功率档加权计算，每小时更新，三档阈值提醒并带冷却；提醒到下单全程归因；材料码带签名防伪。BL3 不建新的设备链路，全部消费 BL1 已上报的 laser_hours、功率档分布与事件留痕，并把 health 交给 BL4 做参数校正、交给 BL6 做保修判定。与《xTool AIoT 平台技术方案》§6 / §17 及 docs/tech-design-bl4-software-content.md §9 一一对应。

  • P0 必须 数据基础，已随 BL1 P0 落地（laser_hours、功率档、事件留痕），本文只引用不重复
  • P1 应该 BL3 本体：健康度、提醒、下单归因、材料识别与防伪，BL1 P0 出口后两个迭代
  • P2 可以 镜片污染估计、寿命预测模型升级、材料 GMV 运营与社区材料库

01背景与目标

1.1 问题

  • 激光模块是消耗品，寿命与发光时长、功率档强相关，但用户只能凭「切不透了」判断。模块衰减是渐进的，用户往往先怪材料、再怪参数，最后才想到模块，期间浪费大量材料并产出差评。
  • 镜片污染让同一参数效果变差，清洁一下就能恢复，但用户不知道该清洁了；客服每天大量工单最终答案是「擦一下镜片」。
  • 耗材复购在电商渠道与设备完全割裂：用户不知道该买哪个型号，买错件是售后主要退货原因之一；官方无法度量「提醒 → 下单」的转化，营销靠盲发。
  • 材料参数是用户最大的知识门槛（BL4 已述）。官方材料包上有码但没有用起来，扫一下就带出参数、记录进加工历史，是最低成本的参数入口，也是材料 GMV 的抓手。

1.2 目标

  1. 可度量：每台设备的激光模块健康度每小时更新，0 到 100，口径公开、可解释、可回溯。
  2. 可预测：给出预计到期时间，误差在 P1 达到 ±20%（以实际更换时间为准），P2 收敛到 ±10%。
  3. 可复购：三档提醒到 App 与 XCS，一键跳转到正确 SKU，提醒到下单全程归因，转化率可度量。
  4. 可识别：材料包码扫描带出官方参数档，识别记录进加工记录，假码可拒。
  5. 数据外供：health 与 laser_hours 以稳定接口供 BL4 校正、BL6 保修使用，本文保证口径与新鲜度。

1.3 北极星与护栏指标

指标 定义 目标 类型
耗材复购率 12 个月内至少购买一次官方模块或镜片的活跃设备 / 活跃设备 P1 ≥ 15% 北极星
提醒到下单转化率 带 reminder_id 的订单 / 发出的提醒数（30 天窗口） P1 ≥ 8% 北极星

02用户、场景与用户故事

2.1 目标用户

  • 家庭创客：一年切几十次，模块寿命长，最怕「买了模块发现不匹配」；对提醒敏感，多一次就关。
  • 小微工作室：模块半年到一年换一次，停机就是损失；愿意为「提前备件」付费，需要准确的到期预测。
  • 教育机构（BL5）：多机统一采购，需要按班级或校区汇总健康度与耗材需求；本文只保证单机口径可聚合。

2.2 核心用户故事

US-1 知道模块还能用多久 作为工作室用户，我希望在 App 与 XCS 看到激光模块健康度和预计到期时间，这样我能提前备件而不是切到一半停机。
US-2 该清镜片时提醒我 作为用户，我希望机器切出来变焦或切不透时，系统先提示我「可能是镜片脏了，先清洁试试」，而不是让我反复调参数。
US-3 一键买对的件 作为用户，我希望提醒里直接给出适配我这台机器的模块型号和购买链接，点一下就到商品页，不用自己查兼容性。
US-4 扫码带出参数 作为用户，我希望扫材料包上的码，XCS 就自动选中这个材料并带出官方参数，切完的记录里也标记了是哪种材料。
US-5 别被假材料坑 作为用户，我希望扫到非官方或假冒材料码时系统告诉我，而不是给出不适用的参数烧坏材料。
US-6 不被骚扰 作为用户，我希望耗材提醒一周最多一次、不在加工中弹出，并且可以关闭；关闭后安全告警不受影响。

03范围：P1 做什么、不做什么

P1 范围内 明确不做（留给 P2 或其它业务线）
激光模块健康度：发光时长 × 功率档加权 + 事件惩罚，小时级批计算，写 consumable_health(part=module) 镜片污染的物理模型（P2，先做启发式提示）
预计到期时间线性外推与三档提醒 80 / 50 / 20 机器学习寿命预测（P2）
提醒冷却：同 SN 同 part 7 天一次；加工中不弹；用户可关 提醒的个性化时段与渠道选择
SKU 映射：part × product_key × module_model → 商城 SKU；下单跳转带 reminder_id；归因与转化率 商城、库存、支付、物流（集团电商平台）
材料码识别：QR / NFC → material_id → BL4 param-svc 带出参数；识别记录进 job_record.material_id 材料 GMV 的营销运营（P2）
材料码防伪：签名校验、一码多次扫描阈值 材料包溯源与批次召回（P2）
health / laser_hours 外供接口给 BL4 校正、BL6 保修 保修判定逻辑本身（BL6）
净化器滤芯 part=filter 的表结构预留 滤芯寿命计算（BL2，按风量）

04功能需求

编号 FR-3xx。每条给需求、验收标准与平台能力（工程仓库中的服务），便于研发拆任务与测试写用例。

4.1 模块健康度计算

编号 需求 验收标准 平台能力
FR-301 P1 激光模块健康度 health ∈ [0, 100]：加权发光时长 = Σ(小时发光时长 × 功率档权重)，权重按功率档分段（如 ≤ 50% 档 1.0、51 到 80% 档 1.3、> 80% 档 1.8），health = 100 × (1 − 加权时长 / 额定加权时长) 再减事件惩罚（OVER_TEMP 每次 −0.5，上限 −10） 口径文档公开；同一输入两次计算结果一致；额定时长与权重按 product_key × module_model 配置并版本化 health-svc 小时批；telemetry_1h、events
FR-302 P1 每小时批计算全部在线过的设备，写 consumable_health(sn, part='module', health, used_hours, predicted_eol_at)；输入缺失时不更新而不是写 0 批作业 P95 < 10 min 完成；缺输入设备计数进看板；health 单调不增（换模块除外） consumable_health 复用不改
FR-303 P1 换模块识别：module_model 变化或 laser_hours 回落到接近 0 且持续 → 判定为更换，health 重置为 100，记录更换事件用于预测误差校准 模拟器 -module-swap 剧本：更换后 health 回到 ≥ 98 health-svc 更换判定；module_swap 表
FR-304 P1 预计到期 predicted_eol_at：按近 30 天加权时长的日均速率线性外推到 health=20 日均速率为 0 时不给预测；预测误差进看板 health-svc
FR-305 P1 外供接口：GET health by SN（health、used_hours、predicted_eol_at、updated_at、model_version），供 BL4 校正与 BL6 保修 P99 < 50 ms；updated_at 超 3 小时视为陈旧，调用方可据此降级 health-svc HTTP
FR-306 P2 寿命预测升级为分位数回归，给出 P10 / P50 / P90 到期区间 误差中位数 ≤ 10% reco 类离线批

4.2 提醒与冷却

编号 需求 验收标准 平台能力
FR-311 P1 health 首次跨越 80 / 50 / 20 三档时各提醒一次（App 推送 + XCS 角标），文案分级：关注 / 建议备件 / 建议更换 每档只提醒一次；跨档回升不重复；用户可查提醒历史 health-svc 提醒判定；alert-svc 非安全通道
FR-312 P1 冷却：同 SN 同 part 7 天内最多一次提醒（含跨档）；设备在作业态（work_state ∈ {1, 2}）时延后到空闲 7 天内第二次跨档只记录不推送；作业中不推送 health_reminder 表、影子 work_state
FR-313 P1 用户可在 App 关闭耗材提醒（按 part），关闭不影响任何安全告警与任务通知 关闭后 0 推送；安全告警链路无依赖 desired consumable_notify_optout；架构约束
FR-314 P1 提醒内容含：当前 health、预计到期、适配 SKU、一键购买按钮、「已更换」按钮（用户手动标记更换，触发 health 重置校验） 点击「已更换」后 24 小时内 health 重置或提示未检测到更换 health-svc、BL4 App
FR-315 P2 镜片清洁提示：同功率下 burnt / uncut 标记比例较该设备基线上升 ≥ 2 倍且腔温、风扇正常 → 概率型提示「可能需要清洁镜片」，明示为启发式 提示不计入三档提醒冷却；用户可反馈「清洁后好了 / 没用」 health-svc lens 启发式；BL4 job_feedback

4.3 一键下单与归因

编号 需求 验收标准 平台能力
FR-321 P1 SKU 映射表：part × product_key × module_model → sku_id、商品名、兼容说明；运营维护，双人审批 试点机型全部模块与镜片有映射；无映射的提醒不显示购买按钮而显示「联系客服」 sku_mapping 表（全局库）
FR-322 P1 一键购买：提醒中的按钮跳转商城商品页，URL 带 reminder_id 与 sn 后四位；商城下单回调携带 reminder_id 跳转 P99 < 1 s；回调幂等 health-svc 归因接口；集团商城
FR-323 P1 归因：reminder_id → 订单 → 转化率；30 天归因窗口；同一 reminder 只归因一次 转化率口径与商城对账差 < 1% reminder_attribution 表
FR-324 P1 商城返回无货或链接失效时，提醒降级显示「暂时缺货，到货通知我」 死链率 0 SKU 可售状态同步
FR-325 P2 教育与工作室多机汇总：按账号聚合各设备 health 与预计需求量，一键批量采购 与 BL5 Fleet 视图共用 BL5

4.4 材料识别与参数带出

编号 需求 验收标准 平台能力
FR-331 P1 官方材料包码（QR 与 NFC 同一编码）：code → material_id、批次、厚度；XCS 与 App 扫码后自动选中材料并调用 BL4 param-svc 带出官方参数档 扫码到参数带出 P95 < 1.5 s；离线时用本地缓存的材料字典 health-svc 材料码解析；BL4 param-svc
FR-332 P1 识别记录：本次加工的 material_id 与 material_code_id 随 JOB_START 上报（复用 BL4 物模型 v1.1 字段），未 opt-in 时不上报 与 BL4 FR-413 同一闸门 job_record.material_id
FR-333 P1 材料字典新增字段：官方 SKU、每包数量、推荐模块；材料页可一键购买（复用 4.3 归因） 材料页购买按钮带 reminder_id（类型 material） material 表扩展、sku_mapping
FR-334 P2 社区材料库：非官方材料由用户创建并分享参数（复用 BL4 FR-427） 需审核 BL4 内容平台

4.5 材料防伪

编号 需求 验收标准 平台能力
FR-341 P1 材料码带签名：code = material_id + 批次 + 序号 + 签名（截断 HMAC 或 ECDSA），客户端本地可验格式，云端验签名 伪造码 100% 被拒；离线时仅格式校验并标注「未联网验证」 health-svc 验码接口；密钥在 KMS
FR-342 P1 同一码被扫描次数阈值：同码 30 天内被 > 5 个不同账号扫描 → 标记可疑，提示用户并进看板 阈值可配；不阻断加工 material_code_scan 表
FR-343 P1 假码或可疑码扫描时：不带出参数，提示「无法验证为官方材料，请手动选择材料」；不做任何自动降级参数 假码扫描后 param-svc 不被调用 客户端逻辑
FR-344 P2 批次召回：按批次号标记问题材料，扫码时提示 — material_batch 表

4.6 数据外供与保修支撑

编号 需求 验收标准 平台能力
FR-351 P1 BL6 保修判定所需数据：累计发光时长、加权时长、功率档分布、OVER_TEMP 次数、更换记录，按 SN 与时间窗查询 接口文档与口径版本化；BL6 验收 health-svc 查询接口；telemetry_1h、events

6.3 数据归属与保留

  • health 与所有健康度中间量只含 SN；提醒归因只含 user_id 与 reminder_id；两者不在同一张表出现。
  • health_reminder 保留 2 年（保修争议追溯）；material_code_scan 保留 1 年。
  • 用户删号：reminder_attribution 按 user_id 删除；health 数据按 SN 保留（保修需要）但不可关联到人（走 BL1 删除传导）。

10依赖、风险与开放问题

10.1 依赖

  • BL1 平台：telemetry_1h 流新增功率档分布列；events 留痕；影子 module_model 与 work_state。
  • BL4：param-svc 材料带参数；job_feedback 供镜片启发式；App / XCS 卡片与扫码界面。
  • 固件：module_model 热插拔重报（DR-302）；可选 module_hours（DR-303）；LENS_CLEANED 事件（DR-304）。
  • 集团电商：SKU 数据、商品页跳转协议、下单回调带 reminder_id、可售状态同步。
  • 供应链 / 包装：材料包印码与 NFC 写入工位、签名密钥在 KMS、批次号规范。
  • BL6：保修判定所需字段口径确认。

10.2 风险与对策

风险 影响 对策
健康度口径不准，提醒过早或过晚 过早是骚扰与信任损失，过晚是停机 口径版本化可回溯；预测误差进看板；先 80 档「关注」软提醒观察 30 天再放 50 / 20
输入缺失被算成 0 → 大量「需更换」误提醒 提醒风暴、退货 缺失不更新；批作业有缺失率熔断（缺失 > 20% 停止写入并告警）
SKU 映射错 → 买错件 退货、差评 双人审批；映射变更灰度；退货率进看板并按映射版本切片
假码被绕过或密钥泄露 假材料 + 官方参数 → 烧材 密钥在 KMS 可轮换；码状态可吊销；同码多账号阈值
提醒被当成推销 用户关闭甚至关联网 冷却 7 天、加工中不弹、可关；文案先讲安全与效果，再讲购买
health-svc 故障拖累 BL4 校正 校正用陈旧值 接口带 stale 标记，BL4 退回 k=1（已在 BL4 方案）
商城回调丢失 → 归因偏低 转化率失真、运营误判 主动对账补偿；报数字先报对账差

10.3 开放问题

  1. 功率档权重与额定加权时长由固件团队按模块型号给出，还是先用经验值上线后按更换数据回归？建议先经验值 + 版本化，三个月后回归。
  2. 模块自带计时芯片（DR-303）是否进硬件排期？有则换模块识别与保修判定都更可靠。
  3. 提醒是否给复购折扣？涉及合规（不得以利益诱导过度）与定价归属。
  4. 材料码用 QR 还是 NFC 为主？NFC 成本高但防伪强；建议 QR 为主、高价材料加 NFC。
  5. 镜片污染启发式是否在 P1 就做「灰度可见」？建议 P1 只在内部机上跑并记录，不对用户显示。

耗材与材料 AIoT PRD v0.1 · BL3 是 BL1 数据的消费方、BL4 校正与 BL6 保修的数据生产方；P1 做健康度、提醒、归因与材料识别，P2 做镜片模型与预测升级。输入缺失不写 0、提醒有冷却且不影响安全告警、假码不带参数是本文三条不可协商的约束。待校准项：权重与额定时长经验值、模块计时芯片可行性、商城回调协议。
