# 软件与内容 AIoT 产品需求文档

> Product Requirements · BL4 软件与内容

xTool 设备云 BL4 业务线的产品需求：让 xTool App 成为设备云的用户入口，让 XCS（xTool Creative Space）从单机切割软件变成连云的加工工作台，让参数库按机型、材料、激光模块健康度动态校正并由真实加工数据反哺，最终承载云素材与订阅。P0 只交付「入口」：App 六个界面与 XCS 云连接，全部复用 BL1 建成的接入、影子、事件、指令、OTA 五条链路。参数动态校正与数据反哺在 P1，订阅在 P2。与《xTool AIoT 平台技术方案》§1 / §6 / §7 / §10 / §17 及工程仓库 x-aiot 一一对应。

## 01 背景与目标

### 1.1 问题

- BL1 建了设备云，但用户看不见它。联网激活、影子、告警、远程控制、OTA 全部需要一个用户面，这个面就是 App。没有 App 承载，BL1 的六个用户故事一个都无法闭环。
- XCS 是用户每天真正打开的软件，但它与机器只在局域网直连，不知道机器的固件版本、模块健康度、历史加工记录。参数库是静态表，同一材料在新模块和老化模块上切出来效果不同，用户只能反复试切。
- 参数是激光加工最大的知识门槛，也是社区最活跃的内容。这些知识目前散落在论坛，官方没有回收通道。每天上万次真实加工的结果没有被记录，更没有反哺参数库。
- 云素材与订阅是软件业务线的收入目标，但前提是 App 与 XCS 有稠密的日活。没有入口，订阅无从谈起。

### 1.2 目标

1. **入口**：App 成为设备云唯一用户入口，BL1 的联网激活、影子、告警、控制、OTA 全部在 App 里可用；XCS 用同一账号看到云端设备与其状态。
2. **参数**：参数库按机型、模块、材料版本化管理，云端分发，客户端离线可用；P1 按模块健康度动态校正，加工结果反哺推荐。
3. **内容**：云素材库与订阅在 P2 上线，订阅只影响内容与增值功能，**绝不影响任何安全功能与基础控制**。
4. **数据**：所有反哺数据需用户显式同意，只含 SN 与加工参数，不含图纸内容。

### 1.3 北极星与护栏指标

| 指标 | 定义 | 目标 | 类型 |
|---|---|---|---|
| App 设备绑定率 | 已绑定 App 的激活设备 / 激活设备 | P0 ≥ 60%（与 BL1 联网激活率同口径） | 北极星 |
| 订阅转化率 | 付费订阅用户 / 月活 App 用户 | P2 ≥ 5% | 北极星 |
| 参数推荐采纳率 | 直接使用推荐参数开始加工的任务 / 有推荐的任务 | P1 ≥ 50% | 护栏 |
| 首刀成功率 | 同一材料第一次加工即 JOB_DONE 且用户未在 10 分钟内重做的比例 | P1 较静态参数库提升 15% | 护栏 |
| App 崩溃率 | 崩溃会话 / 总会话 | < 0.5% | 护栏 |
| 数据反哺 opt-in 率 | 同意上传加工结果的用户比例 | 只统计不设目标（合规） | 护栏 |

## 02 用户、场景与用户故事

### 2.1 目标用户

- **家庭创客**：主要用 App 看机器、收告警；用 XCS 做设计与切割；参数靠官方表和社区帖子。
- **小微工作室**：一天十几个任务，最关心「换了新模块参数要不要改」「这块新材料怎么切不焦」；愿意为省时间的内容付费。
- **XCS 老用户**：习惯局域网直连，对联网敏感，不能因为云功能让原有本地流程变慢或变复杂。

### 2.2 核心用户故事

> **US-1 一个 App 管机器** 作为用户，我希望配网、看状态、收告警、远程暂停、升级固件都在同一个 App 里完成，不用在多个入口之间切换。

> **US-2 XCS 看得见云端机器** 作为工作室用户，我希望在 XCS 里用同一账号看到我所有机器是否在线、在做什么、固件是否最新，而不是只能连局域网里的那一台。

> **US-3 参数跟着机器走** 作为用户，我希望选好材料后 XCS 自动带出适合我这台机器、这个模块、当前健康度的参数，而不是通用表里的默认值。

> **US-4 我的结果帮到别人** 作为用户，我希望切完一块材料后能一键标记「效果好 / 太焦 / 没切透」，让参数库越用越准；但我要能选择不上传，且上传的不能包含我的图纸。

> **US-5 参数库离线可用** 作为用户，我希望断网时 XCS 照常能用上次同步的参数库，联网后自动更新，不会因为云端故障切不了东西。

> **US-6 订阅不绑架安全** 作为用户，我希望不订阅也能收到火焰告警、能远程停机、能升级固件；订阅只解锁素材和高级功能。

## 03 范围：P0 做什么、不做什么

| P0 范围内 | 明确不做（留给 P1 / P2） |
|---|---|
| App 六个界面：配网、设备卡片、告警中心、指令面板、隐私开关、OTA 设置（承载 BL1 FR-01 到 FR-32 的用户面） | 多用户共享设备与角色（P1，仅 owner） |
| XCS 云连接：同账号登录、设备列表与在线状态、当前任务进度只读 | XCS 云端下发加工任务（P1，需白名单扩展与空闲校验） |
| 参数库 v1：静态表按机型 × 模块 × 材料版本化，云端分发，客户端离线缓存 | 按模块健康度动态校正（P1，依赖 BL3 consumable_health） |
| 加工记录上报：JOB_START / JOB_DONE 携带材料与参数标识（opt-in） | 结果标记与推荐模型（P1） |
| 参数库读取接口与版本回滚 | 云素材库、订阅、支付（P2） |
| 反哺数据 opt-in 开关与隐私文案 | 社区参数分享与评价（P2） |

## 04 功能需求

编号 FR-4xx，避免与 BL1 的 FR-01 到 FR-32 冲突。每条给需求、验收标准与平台能力。

### 4.1 App 作为设备云入口

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-401 **P0** | 配网与绑定：BLE 传递 Wi-Fi 凭据，设备上线后自动出现在「我的设备」；同一账号重复绑定幂等 | 承载 BL1 FR-01 / FR-03；配网到显示在线 ≤ 30 s | bootstrap-svc、device_binding uk_binding_active |
| FR-402 **P0** | 设备卡片：在线 / 离线、工作状态、进度、剩余时间、腔温、功率档、固件版本，数据新鲜度 ≤ 30 s；离线时显示最后上报时间 | 承载 BL1 FR-05 / FR-14；与设备屏幕一致 | deviceapi GET /shadow |
| FR-403 **P0** | 告警中心：安全告警列表（未读 / 已推送 / 已确认 / 已处理）、事件时间、类型、快照；「我已处理」按钮；历史可查 | 承载 BL1 FR-09 到 FR-11；ack 后状态不可逆 | alarm-svc GET /alarms、POST /ack、POST /close |
| FR-404 **P0** | 指令面板：暂停、停止、自检三个按钮；离线设备按钮置灰并提示；回执超时 10 s 提示未知结果 | 承载 BL1 FR-17 / FR-18；remote_restart 不出现在界面 | deviceapi POST /cmd、GET /cmds/{id} |
| FR-405 **P0** | 隐私开关：摄像头云端存储、加工数据反哺、营销用途三个独立开关，默认全关；每个开关有独立说明文案；撤回后触发删除传导 | 承载 BL1 FR-30；开关值走 desired 下发并以 reported 为准显示 | PATCH /desired camera_cloud_optin、job_feedback_optin |
| FR-406 **P0** | OTA 设置：自动升级 / 提醒两档；版本说明；升级进度；可推迟 24 h | 承载 BL1 FR-21 / FR-25 | ota-svc、ota_device_task |
| FR-407 **P0** | 操作审计页：谁在什么时候对我的机器做了什么（App / 客服 / Agent） | 承载 BL1 FR-19；客服操作用户可见 | cmd_audit |
| FR-408 **P1** | 多用户：owner 可邀请成员，成员可看状态与收告警，不可下指令与改隐私开关 | 角色写 device_binding.role；越权 403 | device_binding role |

### 4.2 XCS 云连接

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-411 **P0** | XCS 用与 App 相同的账号登录，设备列表与 App 一致，显示在线状态、固件版本、当前任务进度（只读） | 列表与 App 差异 0；状态刷新 ≤ 30 s | deviceapi GET /shadow，账号体系复用 |
| FR-412 **P0** | XCS 局域网直连流程不变；云端只读状态不影响本地连接与加工性能 | 云端不可达时 XCS 本地功能 100% 可用；无新增阻塞调用 | 客户端超时与降级 |
| FR-413 **P0** | XCS 开始加工时向设备下发任务元数据（job_id、材料 id、参数档 id），设备随 JOB_START / JOB_DONE 事件上报 | events 中 JOB_* 携带 job_id / material_id / param_profile_id；未 opt-in 时字段为空 | 物模型 v1.1 任务事件扩展 |
| FR-414 **P1** | XCS 云端下发加工任务到在线且空闲的设备：文件经对象存储预签名 URL，指令 action=job_start | 白名单扩展需二次评审；非空闲设备拒绝；作业中不可下发 | deviceapi 白名单扩展、影子 work_state 校验 |
| FR-415 **P1** | XCS 显示模块健康度与建议（来自 BL3） | 与 App 显示一致 | consumable_health |

### 4.3 参数库

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-421 **P0** | 参数库 v1：按 product_key × 模块型号 × 材料 id 组织，每条含功率、速度、遍数、频率等；整库版本化，发布带版本号与变更说明 | 覆盖试点机型全部官方材料；版本可回滚；发布需双人审批 | param_profile 表（全局库）、发布接口 |
| FR-422 **P0** | 客户端拉取：按机型增量同步，本地缓存，断网可用；版本不一致时提示更新 | 同步 P99 < 2 s；断网 XCS 参数可用 | GET /api/v1/params?product_key=&since_version= |
| FR-423 **P0** | 用户自定义参数：本地保存并可选同步到账号，多端一致 | 自定义参数不进官方库；同步 opt-in | user_param（分片库，只含 user_id） |
| FR-424 **P1** | 动态校正：按模块 laser_hours 与 BL3 健康度对功率 / 速度做校正系数，校正范围有上下限，校正原因对用户可见 | 校正系数 ∈ [0.8, 1.25]；显示「因模块使用 320 h，功率已上调 6%」 | consumable_health、telemetry_1h laser_hours |
| FR-425 **P1** | 结果反哺：JOB_DONE 后 XCS / App 提示一键标记「好 / 太焦 / 没切透」，随 job_id 上报；聚合后进入推荐 | 只上传 SN、job_id、材料、参数、标记，不含图纸；未 opt-in 不提示 | job_feedback 表、聚合任务 |
| FR-426 **P1** | 推荐：同机型同模块同材料的标记聚合达到样本阈值后，生成推荐档并标注样本数与置信度；官方档与推荐档并列 | 样本 ≥ 30 才生成；推荐不覆盖官方档 | 推荐服务（离线批处理） |
| FR-427 **P2** | 社区参数：用户可公开分享参数档，他人可用可评价 | 需内容审核；分享者可撤回 | 内容平台 |

### 4.4 远程监控承载

| 编号 | 需求 | 验收标准 | 平台能力 |

### 4.5 云素材与订阅

| 编号 | 需求 | 验收标准 | 平台能力 |
|---|---|---|---|
| FR-441 **P2** | 云素材库：官方与合作方素材，按机型与材料标签检索，XCS 一键导入 | 导入后本地可用；版权信息随素材 | 内容平台、对象存储 |

## 05 客户端（App / XCS）需求

| 编号 | 需求 | 说明 |
|---|---|---|
| CR-01 **P0** | App 与 XCS 共用账号体系与设备列表接口 | 同一 user_id，同一 device_binding |
| CR-02 **P0** | 云功能全部可降级：云端不可达时 App 显示最后已知状态并标注时间，XCS 本地流程零影响 | 任何云调用有超时（读 3 s、写 5 s），不阻塞 UI 主线程 |
| CR-03 **P0** | 参数库本地缓存与版本号；启动时后台增量同步 | 缓存损坏回退到内置出厂版本 |
| CR-04 **P0** | 隐私开关的显示值以设备 reported 为准，desired 已发未回报时显示「同步中」 | 避免用户以为关了实际没关 |
| CR-05 **P0** | 崩溃与性能上报（不含用户内容）；崩溃率进看板 | 复用集团 APM |
| CR-06 **P0** | 指令按钮防抖：同一指令回执未返回前不可重复点击 | 对应预推演 INC-14 |
| CR-07 **P1** | XCS 任务元数据在本地生成 job_id（UUID），随局域网加工指令下发给设备 | 设备原样带回 JOB_* 事件 |
| CR-08 **P1** | 结果标记提示只在 JOB_DONE 后 10 分钟内出现一次，可关闭 | 不打扰 |
| CR-09 **P2** | 订阅状态本地缓存 24 h，过期前后台刷新 | 离线仍可用已解锁内容 |

| 分片库 | job_record | job_id PK, sn, material_id, param_profile_id, params_hash, started_at, finished_at, outcome | 只含 SN；opt-in 才写 |
| 分片库 | job_feedback | job_id PK, sn, rating(good/burnt/uncut), created_at | 只含 SN |

| 全局库（P2） | asset、entitlement、subscription | — | 内容与订阅，随 P2 设计 |

### 6.3 数据归属与保留

- 参数库与材料字典：全局库，长期保留，版本只增。
- 加工记录与反哺标记：分片库，只含 SN，保留 2 年；用户撤回 opt-in 后停止写入并删除既有记录（走 BL1 删除传导）。
- 图纸与加工文件：**不上云**（P1 云端下发任务除外，且经预签名 URL 24 h 生命周期，不持久化）。
- 推荐模型输入只用聚合后的匿名统计，不回溯到单个 SN。

## 07 非功能需求与 SLO

| 维度 | 要求 |
|---|---|
| 参数库读取 | GET /params P99 < 200 ms；增量同步 P99 < 2 s |

## 10 依赖、风险与开放问题

### 10.1 依赖

- **BL1 平台**：deviceapi、alarm-svc、ota-svc 接口冻结；物模型 v1.1 扩展进固件排期。
- **XCS 团队**：账号登录、设备列表、job_id 生成与下发、参数库同步四个改动点。
- **BL3**：consumable_health 与 laser_hours 降采样是 P1 动态校正的输入。
- **固件**：module_model 上报、JOB_* 事件带 job_id 与材料参数字段。
- **法务**：反哺数据的同意文案、图纸不上云的承诺、推荐结果的免责声明。
- **支付与内容平台**（P2）：集团支付、素材版权与审核。

### 10.2 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 动态校正把参数调错，烧坏材料甚至起火 | 安全与信任 | 校正系数硬上限 [0.8, 1.25]；校正原因可见；用户可一键回到官方档；起火类安全事件与推荐档关联统计，异常即下线该档 |
| XCS 云功能拖慢本地加工 | 老用户流失 | CR-02 强制降级与超时；云调用不在加工关键路径 |
| 反哺数据被认为泄露图纸 | 隐私争议 | 只传参数与标记，不传文件；数据字典审计；文案明示 |
| 推荐档样本被少数用户刷偏 | 参数质量 | 样本阈值 30；按 SN 去重；异常标记率检测 |
| 订阅误伤安全功能 | 品牌与合规风险 | FR-443 做成架构约束与代码审查项 |
| App 与 XCS 两个团队节奏不一致 | 入口体验割裂 | 共用接口与设备列表契约，先冻结后开发 |

### 10.3 开放问题

1. XCS 云端下发任务（FR-414）是否进 P1？涉及指令白名单扩展与文件上云，需安全与法务同时评审。
2. 推荐档是否允许覆盖官方档的默认选中？建议并列展示，默认仍官方档。
3. module_model 能否由固件可靠上报，还是需用户在 App 手动选择？
4. 反哺 opt-in 是否给积分或订阅折扣？涉及合规（同意不得以利益诱导过度）。
5. 订阅定价与 BL3 耗材复购的组合策略归哪条业务线主导。
